# Староміська 78а — MQTT вебпульт (тестова версія 0.1)

Статична HTTPS-сторінка для GitHub Pages. Підключається до EMQX Cloud через MQTT over WebSocket Secure (WSS).

## Файли для кореня репозиторію
- `index.html`
- `style.css`
- `app.js`
- `.nojekyll`

## Публікація через GitHub Pages
1. Завантажте чотири файли в **корінь** репозиторію (не саму папку `staromiska_remote`).
2. Відкрийте **Settings → Pages**.
3. Виберіть **Deploy from a branch**, гілка **main**, папка **/(root)**, **Save**.
4. Дочекайтеся посилання `https://<username>.github.io/<repository>/`.
5. Відкрийте його в Safari, введіть пароль MQTT і натисніть «Підключитися».

## Безпека
- **Ніколи не додавайте MQTT-пароль у файли GitHub**. Він вводиться у формі й не зберігається у localStorage.
- Для віддаленого доступу краще створити **окремого MQTT-користувача** з мінімальними правами (ACL). Не використовуйте адміністраторський обліковий запис брокера.
- GitHub Pages — публічний сайт. Це не автентифікація; доступ до MQTT визначається обліковими даними брокера.
- Залежність mqtt.js завантажується з unpkg.com. Для повністю автономної публікації її можна пізніше включити локально.
- Не залишайте пароль у формі на чужому пристрої. Кнопка «Відключитися» очищає поле пароля.

## Що перевіряє версія 0.1
- WSS-підключення до EMQX Cloud.
- Підписку `garden/controller/#` і отримання повідомлень.
- Ручну публікацію MQTT-повідомлень у відому тему.

**Це ще не готовий пульт керування котлом, освітленням і поливом.** Теми команд та підтвердження стану треба звірити з фактично встановленою прошивкою ESP32-S3. Публікація в MQTT не доводить виконання команди пристроєм.

Якщо EMQX Cloud використовує інший WSS endpoint або шлях, змініть його у формі. Типовий шлях MQTT over WebSocket — `/mqtt`, але фактичну адресу слід перевірити у вашому розгортанні.
