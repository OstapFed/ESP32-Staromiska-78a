# Староміська 78а — вебпульт V22

PWA для **Garden_U V36.1 / V36.2 / ESP32-S3 N16R8**, на основі дизайну V21. Встановлюється на iPhone та Android з GitHub Pages. Полив усіх зон напряму через MQTT потребує V36.2; з V36.1 ці дві команди доступні через локальний шлюз.

## Відкрити

Після публікації: https://ostapfed.github.io/ESP32-Staromiska-78a/

Введіть WSS-адресу брокера, логін і пароль один раз та натисніть **Підключитися**. Типова адреса EMQX Serverless: `wss://<ваш-host>:8084/mqtt`. Базовий topic зазвичай `garden/controller`; він має збігатися з налаштуваннями ESP32.

Збережені налаштування V21 підхоплюються автоматично на тому самому сайті та в тому самому браузері. Наступні відкриття автоматично підключають MQTT. Кнопка **Відключитися** призупиняє підключення до нового відкриття або ручного входу. Автопідключення лише отримує дані й не надсилає команд реле.

Паролі MQTT, Wi-Fi та PIN кожних воріт зберігаються локально у сховищі цього браузера без шифрування. PIN запам’ятовується після першої успішної команди або збереження нового PIN; пароль Wi-Fi — після успішного збереження мережі. Паролі не включені у файли сайту, GitHub, журнал або офлайн-кеш. **Видалити збережені дані** очищає їх із цього пристрою. На іншому телефоні чи після очищення даних браузера потрібне повторне введення. Дані Safari та встановленої PWA можуть мати різні сховища — один раз увійдіть саме у встановленому додатку.

## Керування

Очікування команди одних воріт блокує лише ці ворота: другими можна керувати незалежно. Підтвердження руху залишається окремим для кожних воріт. Полив усіх зон у V36.2 виконується на самій ESP32 через `<base>/water/all/set` або `<base>/water/alltogether/set`, payload `START`, retain `false`. Закриття PWA не перериває чергу чи таймери. Захист від дощу зберігається.

MQTT автоматично підключається зі збереженими параметрами під час відкриття PWA, повернення на її сторінку та відновлення інтернету. При першому введенні повного набору параметрів підключення починається автоматично після виходу з поля; кнопка «Підключитися» також доступна. Дані зберігаються відразу. Явне «Відключитися» призупиняє автопідключення до нового відкриття або ручного входу.

| Меню | Через MQTT без шлюзу | З локальним шлюзом |
|---|---|---|
| Опалення | Стоп, Ручний, Авто, Відпустка; ручна температура ±0,5 °C | Денні/нічні температури й час переходів, температура Відпустки |
| Ворота | Стан двох воріт, відкривання/закривання | Назва, PIN, геркони, імпульс після «Зберегти зміни» |
| Полив | Старт кожної з 4 зон, загальний Стоп; усі зони послідовно/одночасно у V36.2 | Розклади, інтервали, усі зони у V36.1, захист від дощу |
| Освітлення | Вкл/Викл одного каналу GPIO9 | Розклад і дні тижня |
| Датчики | Температура, вологість, батарея, RSSI чотирьох Xiaomi | Назви, MAC, увімкнення, джерело опалення та DS18B20 |
| Інше | Стан контролера, локальний журнал, графік сеансу | Пам’ятка, Wi-Fi, режим HomeKit |

Назви режимів відкривають їхні налаштування, не перемикаючи опалення. Зелена лише кнопка, підтверджена полем `heating_selected_command` контролера. Зміна температури та збереження розкладів не вмикають Авто. Відпустка не має автоматичного завершення.

Особливості наявного MQTT API V36.1: `Ручний → Викл` та `Авто → Викл` надсилають загальний OFF, тому без шлюзу контролер підтверджує й підсвічує **Стоп**. Через шлюз зберігається саме вибрана кнопка «Викл». Під час активної Відпустки зміна ручної уставки доступна через шлюз: нативний topic у цьому режимі змінює температуру Відпустки, тому PWA не використовує його для ручної уставки.

MQTT-команди воріт у цій прошивці авторизуються обліковим записом брокера й **не перевіряють локальний PIN**. Через шлюз PIN перевіряє ESP32. Перед рухом є підтвердження. Стан із герконами показує підтверджене положення/проміжний стан/помилку; без них він позначається як стан за останньою командою. Підтвердження MQTT-імпульсу не означає фізичне досягнення крайнього положення.

## Повні налаштування: локальний шлюз

GitHub Pages працює через HTTPS. V36.1 не має MQTT-команд для всіх налаштувань; HTTP-панель ESP32 недоступна з інтернету. Для повного доступу запустіть включений Python-шлюз на домашньому ПК / Raspberry Pi в тій самій мережі, що ESP32. Він підключається назовні до вашого MQTT-брокера; відкривати порти роутера не потрібно. Доки шлюз не запущений, недоступні форми чесно вимкнені, основні MQTT-кнопки працюють.

1. Установіть Python 3.10+.
2. У папці `gateway` виконайте:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

3. Відредагуйте `.env`: MQTT host без `wss://`, порт TLS `8883`, логін, пароль, base; `ESP_URL` — локальна адреса плати. Якщо панель захищена, задайте її `ESP_USERNAME` та `ESP_PASSWORD`. Дані задаються один раз. Файл `.env` виключений із Git.
4. Запустіть:

```powershell
.venv\Scripts\python gateway.py --env .env
```

Linux/macOS: `.venv/bin/python` замість `.venv\Scripts\python`. Для постійної роботи налаштуйте запуск цієї команди при вході/завантаженні вашої ОС. Шлюз має працювати, поки потрібне дистанційне редагування налаштувань.

Брокер має дозволяти публікацію/підписку `<base>/state`, `<base>/availability`, нативних команд та `<base>/pwa/#` для відповідного облікового запису. Шлюз використовує TLS з перевіркою сертифіката. RPC-запити мають строк дії 20 секунд, не є retained, повторний ID не виконує дію знову. Дозволені лише задані операції; довільні URL/шляхи не приймаються. Після втрати зв’язку команди не відтворюються автоматично.

Шлюз розрахований на HTML/API **V36.1 та V36.2**. Перед збереженням розкладу світла він зчитує поточні налаштування води й дощу та зберігає їх разом: широкий старий `/settings` інакше скинув би їх. Зміни однієї зони поливу так само зберігають інші три. Не редагуйте той самий розклад одночасно з двох клієнтів: прошивка не має версій налаштувань для розв’язання таких конфліктів.

## Встановити PWA

iPhone: Safari → Поділитися → **На початковий екран**. Android: Chrome → меню → **Встановити додаток**. Інтерфейс кешується для відкриття без мережі. Без свіжого стану ESP32 кнопки керування вимкнені; retained-повідомлення саме по собі не підтверджує доступність. Кеш не зберігає команди для подальшого виконання. Для дистанційного керування ESP32, брокер і телефон повинні мати інтернет.

Демо без керування обладнанням: додайте `?demo=1` до адреси. Журнал та графік є даними поточного додатку/сеансу, а не SD-архівом; SD-журнал у V36.1 вимкнений.

## GitHub Pages та розробка

Корінь репозиторію містить готовий сайт для наявної схеми **Deploy from a branch → main → / (root)**. `public/` — його вихідні файли; `gateway/` — додатковий шлюз. Для схеми **GitHub Actions** є `.github/workflows/pages.yml`: тести → збірка → Pages artifact → deploy. Виберіть одну схему в Settings → Pages. Достатньо збереженої схеми main/root; сайт уже зібраний.

Локально потрібен Node.js 22+ без npm-залежностей:

```text
node --test tests/*.test.mjs
python -m unittest discover -s gateway -p "test_*.py"
node scripts/build.mjs
node scripts/serve.mjs
```

Після зміни `public/` повторіть збірку та скопіюйте вміст `dist/` у корінь для main/root, або використовуйте GitHub Actions. Не копіюйте `gateway/.env` чи локальне сховище браузера у репозиторій.

MQTT.js 5.16.1 включено локально у `vendor/` з ліцензією MIT. Під час запуску PWA не залежить від CDN. Оновлення кешу пропонується кнопкою **Оновити** і не стирає збережені паролі.
